# Контракт геометрии вращения FormulFabric (PR #4D)

Документ фиксирует **игровую модель** столкновений при вращении. Он не описывает физику объёмных тел:
FormulFabric — дискретная потактавая игра, и здесь важно ровно одно: какие состояния такта допустимы, а
какие отклоняются, и почему это правило можно проверить повторно.

Документ обязателен к прочтению вместе с `docs/audit-movement-invariants.md` (разделы 3.3, 8 и 9).
Изменение любого правила ниже — изменение правил игры, а не оптимизация.

---

## 0. Термины и координаты

| Термин | Значение |
| --- | --- |
| Гекс | клетка гексагональной сетки, задаётся осевыми координатами `(q, r)` |
| Центр гекса | `hexToWorld((q, r))` — точка `(x, z)` в мировых координатах |
| Радиус гекса `R` | `HEX_SIZE = 1.05` — расстояние от центра до вершины (описанная окружность) |
| Апофема `r_h` | `HEX_SIZE * √3 / 2 ≈ 0.909` — расстояние от центра до середины ребра |
| Соседние центры | на расстоянии `√3 * HEX_SIZE ≈ 1.819` друг от друга |
| Ориентация | pointy-top: вершины гекса — под углами `30° + 60°k`, нормали рёбер — `0° + 60°k` в плоскости `(x, z)` |
| Сфера при проверке маршрута | **точка** в центре своего гекса (модель «центр сферы», см. правило B) |
| Препятствие | **замкнутая** область гексагональной клетки (правильный шестиугольник радиуса `R`) |
| Дуга | непрерывная траектория центра сферы при повороте на 60° вокруг пивота |

Дуга параметризуется углом `θ ∈ [0, ±π/3]`, как и в `movement-intents.ts`:

```
x(θ) = x_c + (x_0 − x_c)·cos θ − (z_0 − z_c)·sin θ
z(θ) = z_c + (x_0 − x_c)·sin θ + (z_0 − z_c)·cos θ
```

где `(x_c, z_c) = hexToWorld(pivot)`, `(x_0, z_0) = hexToWorld(coord)`, а знак угла задаётся `cwSteps`
(`+1` — по часовой стрелке в терминах движка, `−1` — против). Проверено тестом: эта параметризация
совпадает с `rotateAxialOffset(offset, +1)` в `hex-math.ts`, то есть конечная точка дуги равна
`rotateAroundPivot(coord, pivot, cwSteps)`.

Радиус дуги `ρ = |S − P|` — евклидово расстояние между центрами гексов. Оно **не** пропорционально
`hexDistance`: при одной и той же гексовой дистанции разные направления дают разную длину
(например, `(2,0)` — `3.464·s`, а `(1,1)` — `3.000·s`), поэтому радиус всегда считается по мировым
координатам.

## Правило A. Вращение жёсткое

Все сферы одного связанного компонента поворачиваются вокруг общего пивота на одинаковый угол
(`movement-apply.ts` применяет к каждому узлу `rotateAroundPivot(coord, pivot, cwSteps)`).

Следствия, которые обязаны выполняться в каждом допустимом такте:

```
d(A_{t+1}, B_{t+1}) = d(A_t, B_t)      для любых двух сфер одного компонента
R^6 = id,  R^3 ∘ R^3 = id
```

Набор связей (`world.bonds`) при вращении не меняется. Частичное вращение запрещено: при отклонении
такта все сферы остаются на исходных координатах (атомарность).

## Правило B. Статический корпус блокирует дугу

Сфера не может пройти через внутреннюю область гекса, занятого непроходимым корпусом механизма
(`SOLID_MACHINE_TYPES`: `spawner`, `pusher`, `magnet`, `rotator`, `swapper`).

**Модель.** Сфера — точка в центре гекса; препятствие — область гекса. Проверяется не дискретный набор
точек, а непрерывная дуга: гекс считается пройденным, если дуга пересекает его **открытую внутренность**
на интервале параметра положительной длины.

**Касание.** Если дуга только касается границы гекса (ребра или вершины), не заходя внутрь, гекс **не**
считается препятствием. Численное правило: гекс блокирует поворот, если суммарная длина интервалов
параметра, на которых точка дуги лежит внутри замкнутого гекса, больше `1e-7` рад. Порог выбран так,
чтобы быть на несколько порядков выше погрешности `acos`/`hypot` в двойной точности (`~1e-15` рад) и на
несколько порядков ниже любого реального проникновения (минимальный «настоящий» заход в игре — десятые
доли радиана).

**Исключения (существующие правила движка, сохранены без изменений).**

1. Радиус 1 (`hexDistance(coord, pivot) = 1`): дуга идёт по общей границе двух соседних гексов, дуга
   пуста — промежуточных клеток нет.
2. Стартовый гекс сферы (`coord`) не проверяется: дуга начинается в его центре.
3. Гекс назначения (`rotateAroundPivot(coord, pivot, cwSteps)`) не проверяется по дуге: он проверяется
   отдельными правилами движка (корпус в точке назначения, наложение на другие сферы).
4. Гекс пивота не проверяется: на нём стоит сам ротатор, и его корпус иначе блокировал бы любое вращение.

## Правило C. Одновременное движение других сфер

FormulFabric — дискретная потактавая модель, а не непрерывная физическая симуляция. Принятое правило:

| Ситуация в такте | Результат |
| --- | --- |
| Другая сфера **неподвижна** и стоит на промежуточной клетке дуги | вращение запрещено |
| Другая сфера **заканчивает** такт на промежуточной клетке дуги | вращение запрещено (проверка по конечной позиции) |
| Другая сфера **покидает** клетку дуги в этом же такте и её конечная позиция вне дуги | вращение **разрешено** |
| Сфера проходит клетку дуги транзитом (старт и финиш вне дуги) | вращение **разрешено** |
| Две сферы претендуют на одну конечную клетку | срабатывает существующая проверка наложения |
| Встречный обмен | срабатывает существующая проверка обмена (PR #4C) |

Проверка дуги сравнивается **только с предложенными конечными позициями** сфер чужих компонентов
(`proposedCoordByToken`), не с объединением `start ∪ end`. Объединение запрещено: оно блокировало бы
движения, которые движок разрешал и до #4D (например, полимер обгоняет сферу, уезжающую по конвейеру), и
это была бы смена правил, а не исправление дефекта.

**Осознанное ограничение модели.** Промежуточные траектории двух одновременно движущихся объектов не
считаются столкновением: две сферы могут «поменяться местами» через общую клетку, а два вращающихся
полимера — пересечься секторами, если их конечные позиции не конфликтуют. Это свойство дискретной модели,
а не недосмотр; оно зафиксировано тестами (`R60-vacating`, встречные секторы двух ротаторов). Переход к
непрерывным траекториям — отдельное решение о смене физической модели, в #4D не выполняется.

## Правило D. Особые механизмы

| Механизм | Проверка | Что не меняется в #4D |
| --- | --- | --- |
| `rotator` (60°) | дуга центра каждой сферы компонента против корпусов и конечных позиций чужих сфер | теперь дуга точная (правило B) |
| `swapper` (180°) | проверка назначения: корпус в точке назначения, наложение, обмен | дуга 180° **не** добавляется, поведение прежнее |
| `jumper` | проверяется только точка приземления; промежуточный гекс не проверяется | без изменений |
| `conveyor`/`pusher`/`magnet` | обычные проверки края, корпуса, наложения | без изменений |

Новые ограничения ротатора к `jumper` и `swapper` не применяются.

## Правило E. Граница платформы

Движок проверяет выход **конечной** позиции за платформу. В #4D новое правило «падение из-за
промежуточного выхода дуги за край» **не вводится**: это изменило бы существующие уровни. Если такая
ситуация встретится, она фиксируется отдельно (см. `docs/audit-movement-invariants.md`, раздел 10).

## Порядок обхода дуги

`getRotationSweptHexes(coord, pivot, cwSteps)` возвращает гексы в детерминированном порядке:

1. по параметру первого входа дуги в гекс (возрастание `t` по ходу вращения);
2. при равенстве (одновременный вход двух гексов) — по координате: меньший `q`, затем меньший `r`.

Порядок не зависит от порядка `world.tokens`/`world.machines`. Внутри одного гекса сохранён прежний
приоритет классов: сначала корпус механизма, затем чужая сфера. Сферы компонента перебираются в его
каноническом порядке (`getConnectedComponents` → `tokenIds.sort()`).

## Алгоритм точного определения дуги (реализация)

1. **Грубая отбраковка.** Кандидаты — гексы `pivot + offset` для `offset` в диске радиуса
   `⌈(ρ + R)/(√3·R)⌉ + 1`. Гекс отбрасывается, если расстояние от его центра до пивота отличается от `ρ`
   больше чем на `R`: иначе ни одна точка гекса не лежит на окружности радиуса `ρ`.
2. **Точная проверка.** Гекс — пересечение шести полуплоскостей `n_i·x ≤ b_i` (нормали под
   `0° + 60°k`, `b_i = n_i·C + r_h`). Точка дуги `x(t)` лежит в гексе, если для всех `i`
   `n_i·x(t) ≤ b_i`. После подстановки `x(t)` каждое неравенство превращается в
   `cos(σθ − φ_i) ≤ c_i` — на окружности это **один** угловой интервал; пересечение шести интервалов с
   диапазоном дуги даёт точный набор интервалов параметра, где дуга находится внутри гекса.
3. **Решение.** Гекс считается пройденным, если суммарная длина этих интервалов больше `1e-7` рад.
   Первый вход — левая граница первого интервала.

Метод не содержит дискретизации: количество проверяемых точек не зависит от радиуса, а «пропусков между
выборками» не существует по построению. Плотная выборка в тестах используется только как **независимый
детектор расхождений**, а не как эталон корректности.

## Сложность

| Операция | Стоимость |
| --- | --- |
| грубая отбраковка кандидатов | `O(ρ²)` перебора осевых координат в диске радиуса `≈ ρ/(√3R)` |
| точная проверка одного гекса | `O(1)` (6 полуплоскостей, до 6 интервалов) |
| всего на одну сферу | `O(ρ²)` проверок расстояния + `O(ρ)` точных проверок |

Замеры — `scripts/perf-rotation-sweep.ts` (раздел 10 в `docs/audit-movement-invariants.md`). Для
игровых радиусов (до 7 гексов от пивота до платформы в существующих уровнях) одна дуга считается за
единицы–десятки микросекунд, полная проверка компонента — доли миллисекунды на такт. Жёстких порогов
времени в CI нет: корректность важнее микросекунд, а стоимость видна по замеру, а не по обещанию.

## Что этот контракт **не** утверждает

* Он не моделирует объём сферы: сфера — точка, корпус — гекс. Это заявленная модель игры.
* Он не вводит непрерывных столкновений двух движущихся объектов (правило C).
* Он не вводит падений из-за промежуточного выхода за платформу (правило E).
* Он не меняет поведение `jumper` и `swapper` (правило D).
