# Контракт геометрии поворота (PR #4D)

Документ фиксирует модель, по которой считается дуга поворота ротатора и сваппера.
Модель реализована в `src/engine/rotation.ts` и проверяется в
`src/engine/rotation-geometry.test.ts`. Любое изменение этих правил — изменение
игровой механики, а не внутренняя оптимизация.

## 1. Модель

| Понятие | Определение |
| --- | --- |
| Сфера при проверке маршрута | точка в центре своего гекса (радиус сферы в проверке дуги не участвует) |
| Препятствие | замкнутая область гексагональной клетки: шестиугольник с апофемой `r_h = HEX_SIZE·√3/2` |
| Параметр дуги | `t ∈ [0, π/3]` — угол, на который сфера уже повернулась; точка дуги `x(t) = C + R·(cos(β + σt), sin(β + σt))`, где `C` — пивот, `R` — расстояние от пивота до центра сферы, `β` — начальный угол, `σ = ±1` — направление |
| Пройденный гекс | гекс, открытую внутренность которого дуга пересекает на интервале параметра положительной длины |
| Касание границы | ребра или вершины гекса дуга касается, но внутрь не заходит — препятствием **не** считается |

Следствия, которые обязаны выполняться:

1. Результат не зависит от числа точек, частоты выборки или радиуса: алгоритм
   аналитический, дискретизации в рабочем коде нет.
2. Стартовый гекс сферы, гекс назначения и гекс пивота в результат не входят: их
   проверяют другие правила (корпус в точке назначения, наложение, сам ротатор).
3. Радиус 1 даёт пустой список: дуга идёт по общей границе соседних клеток и
   нулевой длины внутри чужих гексов не имеет.
4. Порядок результата детерминирован: по параметру первого входа дуги в гекс,
   при равенстве — по координате (`q`, затем `r`).

## 2. Алгоритм

Гекс задаётся шестью полуплоскостями `n_i·x ≤ b_i`, где `n_i = (cos φ_i, sin φ_i)`,
`φ_i = 60°·i`, `b_i = n_i·C_hex + r_h`. Для точки дуги неравенство превращается в

```
cos(σt + β − φ_i) ≤ (b_i − n_i·C) / R
```

то есть в один угловой интервал на окружности. Пересечение шести интервалов с
диапазоном дуги `[0, π/3]` даёт точный набор интервалов, где сфера находится
внутри гекса; пустой набор или проникновение меньше `1e-7` рад означает касание
либо отсутствие контакта.

Кандидаты перебираются в кольце вокруг пивота: гекс отбрасывается, если
`|dist(центр, пивот) − R| > HEX_SIZE`, то есть если окружность радиуса `R`
вообще не может пройти в пределах описанной окружности гекса. Стоимость одного
поворота не зависит от геометрии уровня и не имеет «слепых зон» между выборками.

## 3. Правило промежуточных траекторий

Занятость гекса дуги проверяется по объединению **«координата на начало такта ∪
предложенная координата»** для всех сфер вне поворачиваемого компонента.

* Сфера, которая покидает сектор в том же такте, всё равно перекрывает дугу в
  момент прохождения поворачивающейся сферы → поворот отклоняется (атомарно, весь
  такт отменяется).
* Сфера, которая в этом такте въезжает в сектор, тоже блокирует поворот.
* Сферы самого поворачиваемого компонента препятствием не являются: они движутся
  вместе с дугой.
* Твёрдый корпус механизма на гексе дуги блокирует поворот всегда.

Иного (разрешённого) пересечения траекторий в движке нет: tick отвергается
целиком, если какое-либо препятствие стоит на дуге.

## 4. Что контрактом не покрывается

* Полный 180°-поворот сваппера: обмениваются две противоположные позиции, а
  промежуточные траектории не моделируются — для сваппера действует отдельное
  правило обмена через пивот (см. `collisions.ts`, исключение swapper).
* Маршрут сфер, которые двигаются линейно (конвейер, толкатель, магнит,
  трамплин): для них проверяется только конечная клетка плюс существующие
  правила наложения, обмена и разлома.
* Проверка корпуса в точке назначения и запрет наложения остаются в
  `collisions.ts` и в контракт дуги не входят.
